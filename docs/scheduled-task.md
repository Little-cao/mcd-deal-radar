# 定时任务配置指南

「麦当劳订阅雷达」的自动推送依赖**宿主智能体平台的定时任务**：
每条订阅 = 一个定时任务，触发频率**由用户在订阅时输入决定**，
默认每天 **12:00 与 24:00** 各触发一次，唤醒智能体调用麦当劳 MCP 检查是否有新动态。

> **平台无关**：本 skill 不绑定特定平台。凡是「能连接麦当劳 MCP + 具备定时任务能力」的
> 智能体平台均可运行，例如 **WorkBuddy**（自动化任务）、**Hermes**（定时任务），
> 或任何支持 Cron / Scheduler 的同类平台。下文说明通用做法，各平台按自身机制落地即可。

---

## 一、怎么创建订阅（= 创建定时任务）

用户只需在对话里说，**并可以顺带说出想要的频率**：

> 「帮我订阅巨无霸套餐，有新品或降价就发我邮箱 me@qq.com」   ← 用默认频率
> 「帮我订阅巨无霸套餐，发到 me@qq.com，**每天早上 8 点**提醒我」  ← 自定义频率
> 「订阅任意新品，**每 3 小时**看一次」                        ← 自定义频率

智能体会：
1. 解析出订阅要素（名称 / 关键字 / 关注维度 / 邮箱 / 城市 / 价格上限）；
2. 解析**检查频率**（用户没说则用默认 12:00 + 24:00）；
3. **向用户复述订阅内容、邮箱与频率**并确认；
4. 在宿主平台上创建定时任务，触发时间采用解析出的频率；
5. 告知用户订阅已生效，且频率随时可改。

---

## 二、频率（`schedule`）由用户输入决定

| 用户怎么说 | 解析为触发时间 |
| --- | --- |
| （未提时间，默认） | 每天 12:00、24:00 |
| 「一天一次」 | 每天 12:00 |
| 「一天两次」 | 每天 12:00、24:00 |
| 「早上 8 点」「每天 8:00」 | 每天 08:00 |
| 「只晚上提醒」「晚上 8 点」 | 每天 20:00 |
| 「只在饭点」 | 每天 11:30、17:30 |
| 「每 3 小时」 | 00:00 起每 3 小时 |
| 「工作日提醒」 | 周一至周五 12:00 |

规则：时间按用户所在时区理解；解析后**必须复述确认**；表达模糊时用默认并说明；
若用户要求高频（＜1 小时/次），提醒「活动按天更新」但尊重用户选择。

## 三、定时任务的任务指令模板

任务内容是一段**给未来智能体看的自然语言指令**（不是命令行），模板如下：

```text
【麦当劳订阅雷达 · 定时检查】
订阅名称：{label}
推送邮箱：{email}
检查频率：{schedule}          # 由用户决定，如「每天 12:00、24:00」
关注维度：{watches}          # new_item / price_drop / new_coupon / campaign
匹配关键字：{keywords}
城市：{city}
价格上限：{max_price}

请执行：
1. 调用麦当劳 MCP 工具获取最新数据：
   - new_item / price_drop → query-meals（必要时 query-meal-detail）
   - new_coupon → available-coupons、query-my-coupons（有门店则加 query-store-coupons）
   - campaign → campaign-calendar
2. 按需调用 now-time-info 判断时效、calculate-price 核价
3. 按「关键字 / 价格上限」筛选出与订阅相关的条目
4. 与上次检查结果比对，只保留【新增或变化】的条目
5. 有新变化 → 整理中文摘要，发邮件到 {email}
      主题：【麦当劳订阅雷达】{label} 有 N 条新动态
   无新变化 → 不发邮件，静默结束
```

## 四、推荐频率

| 频率 | 适用 |
| --- | --- |
| **每天 12:00 + 24:00（默认，推荐）** | 覆盖午市与夜间上新，性价比最佳 |
| 每天 12:00（1 次） | 只想低成本跟踪 |
| 用户自定义（早上 8 点、每 3 小时等） | **完全支持**，按用户输入执行 |
| 高频（＜1 小时/次） | 不建议——活动按天更新，只会徒增调用；用户坚持则尊重 |

> ⚠️ 麦当劳 MCP 限流 600 次/分钟。常规频率下毫无压力。

## 五、各平台落地方式

本 skill 只定义「用什么频率、检查什么、命中后发邮件给谁」，
**具体的定时实现按宿主平台原生机制即可**：

| 平台 | 定时能力 | 落地方式 |
| --- | --- | --- |
| **WorkBuddy** | 自动化任务 | 在「自动化任务」中创建，触发时间设为用户设定的 `schedule`，任务内容填入下方指令模板 |
| **Hermes** | 定时任务 | 在 Hermes 的定时任务中创建，同样填入指令模板 |
| 通用场景 | Cron / Scheduler | 用平台的调度器周期性唤醒智能体，执行指令模板 |

> 只要平台满足「能连麦当劳 MCP + 有定时任务能力」，就能运行本 skill，
> 无需为特定平台修改 skill 内容。

---

## 六、验证订阅是否正常

1. **手动触发一次**：让智能体「现在就检查一下我的巨无霸订阅」，看能否正确调用 MCP；
2. **看定时任务列表**：确认触发时间符合用户设定；
3. **收不到邮件是正常的**：只有检测到**新变化**时才会发信。

---

## 七、修改订阅（含改频率）

用户随时可以说：

| 用户说 | 智能体会 |
| --- | --- |
| 「改成每天一次」 | 把触发时间改为每天 12:00 |
| 「以后只在晚上 8 点提醒」 | 改为每天 20:00 |
| 「每 2 小时检查一次」 | 改为每 2 小时（并提醒频率偏高） |
| 「换一个邮箱」 | 更新任务里的推送邮箱 |
| 「巨无霸那个别推降价了」 | 更新关注维度，去掉降价 |
| 「先停掉」/「删掉」 | 停用/删除对应任务 |
| 「我现在有哪些订阅」 | 列出当前的麦当劳订阅任务及频率 |

改动后智能体会**复述新频率**让你确认。
